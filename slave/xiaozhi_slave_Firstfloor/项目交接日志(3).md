## 二、MQTT 协议详情

### 2.1 MQTT Broker 信息

| 项目 | 值 |
|------|-----|
| **Broker 地址** | `mqtt://8.134.167.240` |

| **Keepalive** | 30 秒 |

### 2.2 Topic 结构

| Topic | 方向 | 用途 |
|-------|------|------|
| `xiaozhi/iot/cmd/{device_id}` | 主机→从机 | 单设备命令（如 `xiaozhi/iot/cmd/1`） |
| `xiaozhi/iot/cmd/broadcast` | 主机→从机 | 广播命令（所有设备都订阅） |
| `xiaozhi/iot/resp/{mac_hex}` | 从机→主机 | 响应包 |
| `xiaozhi/iot/heartbeat/{mac_hex}` | 从机→主机 | 心跳包 |
| `xiaozhi/iot/announce/{mac_hex}` | 从机→主机 | 设备上线宣告 |
| `xiaozhi/iot/sensor/{mac_hex}` | 从机→主机 | 传感器数据 |

### 2.3 二进制协议包结构

**所有命令都是 8 字节二进制包，不是 JSON！**

```c
typedef struct {
    uint8_t command;       // 命令码 (见下表)
    uint8_t device_id;     // 设备 ID (1=一楼, 2=二楼, 3=三楼)
    uint8_t gpio_index;    // GPIO/舵机/灯索引
    uint8_t value;         // 值 (开=1, 关=0, 或舵机角度)
    uint8_t reserved[4];   // 保留字节 (全0)
} __attribute__((packed)) iot_command_packet_t;  // 总共 8 bytes
```

**ANNOUNCE_V2 包结构（28字节，设备上线用）：**
```c
typedef struct {
    uint8_t command;       // 0x08
    uint8_t device_id;     // 设备 ID
    uint8_t gpio_index;    // GPIO 数量
    uint8_t value;         // 保留
    char device_name[24];  // 设备名称（ASCII）
} __attribute__((packed)) iot_announce_v2_packet_t;  // 总共 28 bytes
```

### 2.4 命令码表

| 命令 | 码 | HEX | 用途 |
|------|-----|-----|------|
| SET_GPIO | 0x01 | `01` | 设置 GPIO 电平 |
| GET_GPIO | 0x02 | `02` | 读取 GPIO 状态 |
| HEARTBEAT | 0x04 | `04` | 心跳包 |
| DISCOVER | 0x06 | `06` | 设备发现请求 |
| ANNOUNCE | 0x07 | `07` | 设备宣告（旧版） |
| ANNOUNCE_V2 | 0x08 | `08` | 设备宣告（新版，含名称） |
| SET_SERVO | 0x10 | `10` | 设置舵机角度 (0-180°) |
| SET_LIGHT | 0x11 | `11` | 设置灯光（按索引） |
| SET_RELAY | 0x12 | `12` | 设置继电器（按索引） |
| SENSOR_REPORT | 0x13 | `13` | 传感器数据上报 |
| BROADCAST_ALL_OFF | 0x30 | `30` | 广播：全部关闭 |
| BROADCAST_ALL_ON | 0x31 | `31` | 广播：全部开启 |
| BROADCAST_LIGHTS_OFF | 0x32 | `32` | 广播：灯光全关 |
| BROADCAST_LIGHTS_ON | 0x33 | `33` | 广播：灯光全开 |
| EMERGENCY | 0x34 | `34` | 紧急模式 |

### 2.5 常用命令示例

**广播开灯：**
```
Topic: xiaozhi/iot/cmd/broadcast
Payload (HEX): 33 00 00 00 00 00 00 00
```

**开一楼大门（舵机）：**
```
Topic: xiaozhi/iot/cmd/1
Payload (HEX): 10 01 00 90 00 00 00 00
解释: SET_SERVO(0x10), 设备1, GPIO索引0, 角度90°
```

**开二楼主卧灯：**
```
Topic: xiaozhi/iot/cmd/2
Payload (HEX): 11 02 00 01 00 00 00 00
解释: SET_LIGHT(0x11), 设备2, 灯索引0, 开启(1)
```

### 7.3 已发现问题：别名映射方向错误

**问题根因：**

设备宣告的名称是 `1F_Device`、`2F_Device`、`3F_Device`（ASCII），但 MCP tool 传入的是中文 `"一楼设备"`、`"二楼设备"`、`"三楼设备"`。

当前别名表配置错误：
```c
// bsp_iot_controller.c 当前配置（错误）
{"一楼设备", "一楼设备"},  // 输入"一楼设备" → 输出"一楼设备"
{"1F_Device", "一楼设备"},  // 输入"1F_Device" → 输出"一楼设备"
```

**查找流程：**
```
AI 说 "打开一楼大门"
    ↓
MCP tool: App_IOT_Set_Servo("一楼设备", ...)
    ↓
IOT_Find_Device_By_Name("一楼设备")
    ↓
别名解析: "一楼设备" → "一楼设备" (没变化)
    ↓
在设备列表找 device_name == "一楼设备"
    ↓
找不到！因为设备列表里是 "1F_Device"
    ↓
返回 -1 → 报错 "Remote device '一楼设备' not found"
```

**修改 `bsp_iot_controller.c` 别名表，反向映射：**

## 九、⚠️ 重要注意事项（必读）

### 9.1 不要破坏项目架构

**当前架构是经过深思熟虑设计的：**

1. **两个独立的 MQTT 系统**
   - AI MQTT (`mqtt_protocol.cc`) 和 IoT MQTT (`iot_controller.c`) 是**独立的**
   - 不要尝试合并它们，不要让它们共享同一个连接

2. **别名映射机制**
   - 设备名称通过别名表映射，不要删除 `bsp_iot_controller.c` 中的 `g_device_aliases`
   - 如果从机改名，需要同时更新别名表

3. **MCP 工具层**
   - `iot_mcp_tool.cpp` 是 AI 和 IoT 的桥梁，不要修改 MCP 工具名
   - 不要修改 MCP 工具的参数格式

4. **Topic 前缀**
   - 所有 IoT Topic 使用 `xiaozhi/iot/` 前缀
   - 不要随意修改 Topic 结构

### 9.2 最小化修改原则

**遇到问题时：**

1. **先想清楚问题根因**，不要猜测
2. **用最小修改解决问题**，不要大规模重构
3. **修改前先问 AI 分析**，让 AI 给出方案
4. **修改后立即验证**，不要累积多个修改再测试

### 9.3 让 AI 帮你思考

**告诉你的 AI：**

```
"我要修改代码解决 [具体问题]。
请先分析：
1. 问题根因是什么？
2. 需要修改哪些文件？
3. 修改的最小范围是什么？
4. 有什么风险？
然后给出修改方案，不要直接动手改。"
```

### 9.4 常见错误

| 错误 | 原因 | 正确做法 |
|------|------|----------|
| 设备名 "not found" | 别名表没映射 | 在 `g_device_aliases` 添加映射 |
| MQTT 连不上 | Broker 地址错误 | 确认 `iot_controller.c:126` 地址 |
| 命令没响应 | 从机没订阅 Topic | 检查从机订阅 `xiaozhi/iot/cmd/*` |
| 设备超时 | 60秒无心跳 | 从机需要定期发送 HEARTBEAT |
