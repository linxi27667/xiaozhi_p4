# ESP32-P4 智能家居 LVGL UI 修复计划

> 本计划用于后续分阶段修复。原则是“一次只修一个阶段，上机确认一页，再进入下一阶段”。用户已明确：后续不需要 Codex 编译，只负责修改代码和说明改动。

## 0. 当前问题归纳

### 0.1 聊天页

- 聊天页底部出现“回家 / 关闭所有灯 / AI 中控台”等智能家居自定义内容，和小智源码内置聊天页冲突。
- 时间、Wi-Fi 图标、表情没有在去掉左侧导航后的主内容区域居中。
- 小智原生 `SetEmotion()` / `SetChatMessage()` 应该保留，不再做额外聊天 UI。

### 0.2 总览页

- 温湿度存在假数据/误导性数据风险，真实项目没有室内温湿度传感器。
- 顶部缺少完整状态：Wi-Fi、MQTT、厦门、天气摘要、时间。
- 目前没有使用 TF 卡图片资产，页面视觉仍偏工程调试界面。
- 快捷场景按钮太小，没有 flex 撑满剩余空间。
- Wi-Fi 状态显示错误，根因是 smart-home 数据模型没有同步小智主网络真实事件。

### 0.3 控制页

- 设备卡字体偏小。
- 只有一楼、二楼、三楼筛选，没有“全部”视图。
- 当前布局基础可保留，但需要提升卡片密度、可读性和触控面积。

### 0.4 灯光页与场景页

- 点击灯光/场景后出现看门狗复位，需要优先定位生命周期、事件订阅、内存越界、阻塞回调。
- 灯光页视觉距离设计稿仍远，主卧 WS2812B 需要更强的色彩控制视觉。
- 场景页需要更接近设计稿的卡片化布局，但必须先保证不复位。

### 0.5 环境页

- “无数据”展示占位过多，信息密度和审美不足。
- 需要严格区分“从机上报数据”和“天气服务数据”。
- 不能显示项目不存在的室内 PM2.5、光照、室内温湿度。

### 0.6 网络页与设置页

- 网络页显示 Wi-Fi 状态错误。
- 设置页存在“天气置”等错误/残缺文本，应删除或改成正确项。
- 设置页只保留必要系统信息，不应混入未完成配置入口。

## 1. 全局修复原则

- 保留小智源码聊天链路，不做自定义聊天页。
- 每个智能家居页面独立，不把所有功能塞进一个大页面。
- 数据必须真实：无真实值显示“暂无数据/同步中”，不使用随机数、演示假数。
- 设计上遵循 Cloud White：浅背景、白卡片、细边框、蓝色主色、绿色在线、红色告警、橙色灯光。
- 页面使用 flex/grid 思路，不继续堆硬编码坐标。
- UI 图片走 TF 卡，固件内只保留轻量 LVGL 图形和 Font Awesome 图标。
- 图片缺失不影响功能，自动回退到图标或纯卡片。
- 后续修复顺序按用户上机确认推进，不一次性大改所有页面。

## 2. 阶段 1：聊天页 + 总览页

### 2.1 聊天页目标

- 删除智能家居自定义聊天快捷条和“AI 中控台”角色标题。
- 恢复小智内置聊天显示，只保留原有 `SetEmotion()`、`SetChatMessage()`、`ClearChatMessages()` 行为。
- 修正左侧 Shell 侧栏引入后的居中偏移：表情、预览图、状态文本、时间应在主内容区域居中。

### 2.2 聊天页实现要求

- 在 `lcd_display.h/.cc` 中移除：
  - `chat_quick_bar_`
  - `chat_role_label_`
  - 聊天页场景快捷按钮创建逻辑
  - `SetChatMessage()` 中按 role 改底栏样式的逻辑
- `bottom_bar_` 只作为小智原生字幕容器，不再承担智能家居 UI。
- `SwitchShellPage(Chat)` 时隐藏 `smart_home_page_`，显示小智原有内容。
- `emoji_box_` 和 `preview_image_` 以 `LV_HOR_RES - sidebar_width` 为中心区域计算偏移。

### 2.3 总览页目标

- 按设计稿方向形成“顶部状态 + 家庭概览 + 楼层概览 + 快捷操作 + 图片资产”的完整首页。
- 固定城市为厦门，显示真实联网天气。
- 不再显示假的温湿度；天气数据明确标注为“厦门室外/天气服务”。
- 快捷按钮使用大按钮并 flex 撑满，不再使用小 chip。

### 2.4 总览页数据要求

- 天气位置：
  - `WEATHER_LAT=24.4798`
  - `WEATHER_LON=118.0894`
  - `WEATHER_LOCATION_NAME="厦门"`
  - `WEATHER_TIMEZONE="Asia/Shanghai"`
- 默认天气源继续使用 Open-Meteo Forecast API 和 Air Quality API：
  - Forecast：温度、相对湿度、降水、天气代码、风速。
  - Air Quality：PM2.5、AQI。
  - 官方文档：https://open-meteo.com/en/docs
  - 空气质量文档：https://open-meteo.com/en/docs/air-quality-api
- 国内天气 API 备选：和风天气/QWeather。
  - 官方文档：https://dev.qweather.com/docs/start/
  - 需要 Key，不把 Key 写死进仓库。
  - 本阶段不切换，除非用户提供 Key 并确认。

### 2.5 总览页网络状态同步

- 在小智主网络事件回调中同步 smart-home model：
  - `NetworkEvent::Scanning` -> `WIFI_STATE_SCANNING`
  - `NetworkEvent::Connecting` -> `WIFI_STATE_CONNECTING`
  - `NetworkEvent::Connected` -> `WIFI_STATE_CONNECTED`
  - `NetworkEvent::Disconnected` -> `WIFI_STATE_FAILED` 或 `WIFI_STATE_IDLE`
- `wifi_manager.cc` 仍可保留兼容层，但不能作为真实 UI 状态来源。
- 天气服务只在真实网络连接后请求；失败不伪造数据。

### 2.6 总览页图片资产

TF 卡目录固定：

```text
/sdcard/xiaozhi_ui/
```

第一阶段建议图片：

| 文件名 | 建议尺寸 | 用途 |
| --- | --- | --- |
| `overview_home.png` | 180x120 | 总览家庭主视觉 |
| `weather_xiamen.png` | 96x72 | 厦门天气卡片 |
| `floor_1.png` | 120x84 | 一楼卡片 |
| `floor_2.png` | 120x84 | 二楼卡片 |
| `floor_3.png` | 120x84 | 三楼卡片 |

要求：

- PNG 使用透明背景或浅色背景。
- 单张图片尽量小于 150 KB。
- 不使用全屏大图。
- 图片不存在时页面仍正常显示图标和文字。

### 2.7 阶段 1 验收

- 聊天页不再出现智能家居快捷文字。
- 小智表情和状态位于主内容区域视觉中心。
- 总览页右上角显示 Wi-Fi、MQTT、厦门、天气摘要、时间。
- 天气联网成功后显示真实厦门室外数据；失败显示同步中/暂无数据。
- 总览页快捷按钮变大且等宽铺满。
- 1024x600 下无文字重叠、卡片越界。

## 3. 阶段 2：控制页

### 3.1 目标

- 保留当前较合理的基础布局，重点提升可读性、设备完整性和触控体验。
- 增加“全部”筛选，用户可以一次看到所有真实设备。

### 3.2 实现要求

- 楼层筛选改为四项：全部、一楼、二楼、三楼。
- 默认进入“全部”。
- 设备卡字体放大：
  - 设备名建议 20-22 px。
  - 状态文字建议 16-18 px。
  - 图标建议 24-30 px。
- 卡片高度不小于 96 px，触控区域不小于 80 px。
- 设备状态文案统一：
  - 离线：未接入/离线。
  - 灯类：已开/已关。
  - 舵机类：打开/关闭/角度语义。
  - 风扇：运行/停止。
- 只显示真实设备：
  - 一楼：大门、大厅灯。
  - 二楼：主卧灯、客厅灯、厕所灯、风扇、二楼晾衣杆。
  - 三楼：阳台灯、左天窗、右天窗、三楼晾衣杆。

### 3.3 验收

- 全部/一楼/二楼/三楼四个筛选可切换。
- 全部页能看到所有真实设备。
- 点击设备仍调用现有 MQTT 控制接口。
- 离线设备点击不伪造成功状态。

## 4. 阶段 3：灯光页看门狗修复 + UI 优化

### 4.1 第一优先级：修复复位

- 点击灯光页导致看门狗复位时，先定位是否来自：
  - 页面创建时一次性对象过多。
  - LVGL 事件回调里阻塞发送 MQTT。
  - 页面 delete 后仍收到事件回调。
  - `lv_malloc` 失败后继续使用空指针。
  - 色盘/滑条刷新导致递归事件。
- 修复策略：
  - 页面创建不做网络请求。
  - MQTT 发送保持轻量，必要时只投递命令，不阻塞 UI。
  - 每个页面 ctx 必须有 `deleted` 标记和 `LV_EVENT_DELETE` 退订。
  - 所有动态对象检查空指针。

### 4.2 UI 目标

- 做成设计稿的主卧 RGB 灯控制页，不再是调试控件拼接。
- 主控对象固定为二楼主卧 `WS2812B RGB`。
- 显示在线状态、开关、亮度、RGB、当前效果。

### 4.3 图片与控件

- 色盘优先使用 TF 卡：
  - `/sdcard/xiaozhi_ui/color_wheel_220.png`
- 图片不存在时使用 LVGL 绘制色块/预设色按钮回退。
- 效果只保留真实协议支持：
  - 静态
  - 呼吸
  - 彩虹
  - 警示
- 亮度滑条必须显示百分比。
- 开关状态不能和离线状态混淆。

### 4.4 验收

- 进入灯光页不复位。
- 离线时禁用或弱化控制。
- 在线时开关、亮度、颜色、效果能发出对应 MQTT 命令。
- 1024x600 下色盘、滑条、效果按钮不重叠。

## 5. 阶段 4：场景页看门狗修复 + UI 优化

### 5.1 第一优先级：修复复位

- 和灯光页一样先定位看门狗原因。
- 场景点击只调用 `mqtt_send_scene(scene_id)`，不在 UI 回调内做复杂同步等待。
- 页面销毁时必须退订 `UI_EVENT_SCENE_CHANGED`。

### 5.2 真实场景

只保留协议真实支持的场景：

- 回家
- 睡眠
- 观影
- 起夜
- 雨天收衣
- 离家
- 火警演示

删除或不显示：

- 聚会
- 自动模式
- 任何协议不存在的场景

### 5.3 UI 要求

- 场景卡使用两列或三列 flex/grid。
- 每张卡有图标/图片、场景名、简短动作描述。
- 火警演示使用红色警示样式，并降低误触感。
- 当前场景高亮。

### 5.4 图片资产

建议 TF 卡文件：

| 文件名 | 用途 |
| --- | --- |
| `scene_home.png` | 回家 |
| `scene_sleep.png` | 睡眠 |
| `scene_movie.png` | 观影 |
| `scene_night.png` | 起夜 |
| `scene_rain.png` | 雨天收衣 |
| `scene_away.png` | 离家 |
| `scene_fire.png` | 火警演示 |

### 5.5 验收

- 进入场景页不复位。
- 每个场景点击后 MQTT 发出对应 scene id。
- 当前场景高亮正确。
- 图片缺失时不崩溃。

## 6. 阶段 5：环境页

### 6.1 目标

- 环境页变成“从机传感器 + 厦门室外天气”两大区域。
- 不再出现假的室内温湿度、室内 PM2.5、光照。

### 6.2 室内真实传感器

显示从机真实上报：

- 二楼雨滴值
- 二楼雨滴状态
- 三楼雨滴值
- 三楼雨滴状态
- 三楼烟雾值
- 三楼火灾状态
- 三楼求助状态

无数据时显示“暂无上报”，不显示 0 当作真实值。

### 6.3 室外天气服务

显示厦门室外：

- 温度
- 湿度
- 降水
- 风速
- 天气状态
- PM2.5
- AQI
- 最近更新时间

每个区域明确标注来源：

- “从机上报”
- “天气服务”

### 6.4 验收

- 数据来源清晰。
- 无数据状态不刺眼、不占满整页。
- 有从机数据后对应卡片自动刷新。
- 天气失败时不显示假值。

## 7. 阶段 6：网络页

### 7.1 目标

- 修正 Wi-Fi 已连接但页面显示未连接的问题。
- 网络页只显示真实网络和 MQTT 状态，不依赖 legacy stub。

### 7.2 实现要求

- Wi-Fi 状态来自小智主网络事件。
- SSID 使用网络事件 data 或 Board/Wi-Fi 管理器可获取的真实 SSID。
- MQTT 状态来自 smart-home MQTT 客户端。
- Broker 显示实际 `8.134.167.240:1883`。
- 消息数、控制器状态来自 `mqtt_device_model_t`。

### 7.3 验收

- 设备连上 Wi-Fi 后网络页显示已连接。
- MQTT 未连接/已连接状态准确。
- 从机在线状态准确。
- 不再显示错误 SSID 或错误 broker。

## 8. 阶段 7：设置页

### 8.1 目标

- 删除错误的“天气置”入口。
- 设置页只保留稳定、真实、可解释的系统设置。

### 8.2 保留项

- 网络入口
- 语言
- 屏幕亮度
- 声音
- 固件版本
- MQTT Broker
- 天气城市：厦门
- 设备 ID

### 8.3 删除或暂不显示

- 未实现的运行时天气配置。
- 错别字/截断项。
- 不可用或无效果的入口。

### 8.4 验收

- 设置页没有“天气置”等错误文案。
- 亮度/声音滑条可用。
- 语言切换后页面可读。
- 系统信息真实。

## 9. 阶段 8：视觉统一与设计稿贴近

### 9.1 全局视觉

- 背景：浅蓝白。
- 卡片：白底、细边框、轻阴影、8 px 圆角。
- 主色：蓝色。
- 在线：绿色。
- 告警：红色。
- 灯光：橙色。
- 场景：蓝/紫少量点缀。

### 9.2 侧栏

- 保留当前左侧导航：
  - 聊天
  - 总览
  - 控制
  - 灯光
  - 场景
  - 环境
  - 网络
  - 设置
  - 唤醒
- 当前页高亮更明显。
- 图标和文字不要过淡。
- 唤醒按钮保留蓝色强调。

### 9.3 字体与间距

- 页面标题：22-24 px。
- 卡片主值：24-30 px。
- 设备名：18-22 px。
- 辅助文字：13-16 px。
- 按钮文字：16-18 px。
- 避免小于 12 px 的中文关键文字。

### 9.4 验收

- 上机拍照后，页面能明显接近设计稿的 Cloud White 风格。
- 不是纯文字调试页。
- 不出现文字裁切、重叠、过淡看不清。

## 10. 阶段 9：稳定性与内存

### 10.1 目标

- 消灭切页看门狗复位。
- 保证 LVGL 生命周期正确。
- 避免图片加载导致内存紧张。

### 10.2 检查项

- 每个页面 ctx 都有 delete 回调。
- 每个事件订阅都有退订。
- 页面切换使用 `lv_obj_clean()` 后不残留旧页面回调。
- 图片加载失败有回退。
- 大图片不进入固件，不占用 flash 分区。
- UI 回调不做耗时网络请求。

### 10.3 验收

- 连续切换 50 次页面不复位。
- 连续点击场景/灯光控制不触发看门狗。
- TF 卡缺失时 UI 仍能启动。
- MQTT 离线时 UI 不假成功、不崩溃。

## 11. 推荐实施顺序

1. 阶段 1：聊天页 + 总览页。
2. 用户上机确认聊天页和总览页。
3. 阶段 2：控制页。
4. 用户上机确认控制页。
5. 阶段 3：灯光页复位与 UI。
6. 用户上机确认灯光页。
7. 阶段 4：场景页复位与 UI。
8. 用户上机确认场景页。
9. 阶段 5：环境页。
10. 阶段 6：网络页。
11. 阶段 7：设置页。
12. 阶段 8/9：统一视觉和稳定性压测。

## 12. 每阶段交付格式

每次修复完成后需要给用户说明：

- 改了哪些页面。
- 改动了哪些关键文件。
- 哪些数据是真实来源。
- 哪些功能未验证。
- 需要用户重点上机拍照检查的位置。

不默认编译；除非用户明确要求，Codex 不运行 `idf.py build`。
