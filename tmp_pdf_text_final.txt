基于 ESP32S3/P4 双中枢架构的 AIoT 多模态家居
中控系统
摘要
本项目基于 ESP32-P4 主控芯片与 ESP32-S3 多节点从机架构，构建了一
套面向多层建筑的智能中控系统。系统以“AI 语音交互 + MCP 语义协议 +
MQTT 物联网通信”为核心技术链路，实现语音唤醒、自然语言对话解析、多
楼层设备统一控制、环境信息采集与实时显示、自动场景联动及触屏可视化操作
等功能，形成完整的智能建筑控制闭环。
主控端以 ESP32-P4 为核心，构建事件驱动式系统架构，并基于 LVGL 图
形框架实现触摸屏 UI 界面，用于设备控制、环境数据展示与系统状态监控等操
作。系统通过语音模块实现唤醒词检测与语音输入，并结合云端大语言模型完成
自然语言理解与语义解析，最终通过 MCP 协议完成控制指令生成与任务分发，
实现从语音输入到设备控制的链路贯通。
从机端采用 ESP32-S3 节点，通过 MQTT 协议与主控进行双向通信，实
现控制指令接收与设备状态回传。系统采用“主机决策 + 从机执行”的分布式
架构设计，从机负责 GPIO、舵机、LED 灯带等执行器控制，并通过标准化主题
订阅机制保证通信一致性与实时性。
在执行层设计中，系统采用模块解耦方式，将设备控制抽象为独立执行单元，
由主控下发指令，从机解析后驱动对应硬件资源，实现多设备并行控制与统一管
理。同时系统支持环境传感器数据采集与上传，实现环境信息的实时监测与可视
化展示。
系统内置规则引擎与自动模式控制机制，可根据环境传感器数据触发自动联
动策略。在火焰或雨滴等异常环境条件下，系统通过确认机制触发紧急事件处理
流程，自动执行全楼设备联动控制，包括灯光控制、天窗/衣杆执行机构动作以
及 ASR 语音告警，实现快速响应与安全防护机制。
整体系统采用统一通信协议与模块化设计思路，各功能模块之间低耦合、高
扩展，通过 MQTT 实现设备状态同步与指令传输，构建稳定可靠的物联网控制
网络。系统在工程实现上融合嵌入式系统设计、物联网通信机制、语音交互处理
与多节点协同控制技术，形成一套可扩展的多层建筑智能中控解决方案。

第一部分 作品概述
1.1 功能与特性
本系统是一套完整的多层建筑智能中控平台，核心功能包括：
(1) AI 语音交互：支持离线语音唤醒（ESP-SR），通过 WebSocket/MQTT 协
议接入云端大模型（DeepSeek），实现流式 ASR + LLM + TTS 语音对
话，云端大模型完成用户意图理解，可将复杂语音指令解析为多个设备控
制动作。
(2) MCP 协议设备控制：通过 MCP 实现大模型对 IoT 设备的语义级控制，
支持音量、灯光、舵机、GPIO 、传感器查询等设备工具，实现语义级硬
件控制。
(3) 多楼层分布式 IoT 控制：系统采用 ESP32-P4 作为中控主机，ESP32-S3
（x3）作为楼层从机，三层从机分别管理本层灯光、舵机和传感器设备，
并通过 MQTT 与 P4 中控完成指令下发和状态回传。
(4) 环境传感器监测与报警：系统部署火焰传感器与雨滴传感器等环境感知
模块，实时采集 ADC 数据，超过阈值自动触发报警和联动控制。
(5) 自动场景联动：系统内置规则联动逻辑，支持火灾报警、紧急开门、全
屋灯光警示、天窗通风，以及雨天自动关窗收衣等场景，实现“环境感知
→ 规则判断 → 设备执行”的闭环响应。
(6) 触屏可视化操控：系统基于 LVGL 开发触屏交互界面，包含总览、控制、
灯光、场景、环境、网络和设置等页面，支持设备状态查看、灯光调色、
场景切换和手动控制。
(7) 人脸识别：系统采用本地人脸识别模型，在 ESP32-P4 端完成门口摄像头
画面的人脸检测与身份确认，识别成功后自动联动回家场景，实现无感化
智能体验。

1.3 主要技术特点
(1) 主从分布式架构：系统采用 ESP32-P4 作为中控主机，负责 LVGL 可视
化界面、AI 交互、MCP 工具调用、设备调度和本地人脸识别；ESP32-S3
作为楼层从机，负责本层灯光、舵机、继电器和传感器设备控制，形成“P4
中控决策 → S3 从机执行 → 状态回传”的分层架构。
(2) Flag-Driven + Enum 设备模型：从机端将灯光、继电器、舵机等设备
状态统一抽象为枚举类型和标志位，MQTT 接收任务只负责更新状态，设
备刷新任务周期性读取标志位并驱动 GPIO、PWM 或继电器输出，实现“指
令接收 → 标志位更新 → 硬件执行”的解耦流程。
(3) MQTT 二进制协议：系统自定义紧凑二进制包格式（8 字节命令包、64
字节心跳包），相比 JSON 序列化减少 70% 以上带宽开销，更适合嵌入
式设备间的高频状态同步与低开销通信。
(4) 事件驱动 + 观察者模式：主机端使用 FreeRTOS 事件组驱动主循环，通

工具调用机制引入智能家居控制链路。用户既可以发出“把二楼卧室灯调

硬件联动的智能控制。

定义轻量化 MQTT 设备控制协议。主机可通过云端 MQTT Broker 对不同
楼层从机进行单播控制、广播控制和传感器状态接收，实现多楼层、多设

2.2.2 机械设计介绍
系统以三层别墅模型为物理载体，每层楼板部署对应的 ESP32-S3 从机开发
板与执行器，各楼层设备由本层从机独立管理，并通过 MQTT 与 ESP32-P4 中控
协同：
• 一楼：主要模拟入户区域，包含大门舵机和大厅灯。其中，大门舵机用于
模拟门锁开关动作，大厅灯通过 GPIO 高低电平控制，同时预留一楼总闸
控制引脚。
• 二楼：主要模拟生活起居区域，包含主卧灯、客厅灯、厕所灯、风扇继电
器、预留继电器、晾衣杆舵机以及 WS2812 RGB 灯带。其中，主卧灯采用
WS2812 RGB 灯带实现氛围灯和颜色调节，客厅灯与厕所灯通过 GPIO 控
制，风扇及预留设备通过继电器控制，晾衣杆由舵机模拟伸缩动作。
• 三楼：主要模拟阳台与安全感知区域，包含阳台灯、左天窗舵机、右天窗
舵机、晾衣杆舵机、火焰传感器和雨滴传感器。其中，阳台灯通过 GPIO 控
制，三个舵机通过 LEDC PWM 输出控制，火焰传感器接入 GPIO2
（ADC1_CH1），雨滴传感器接入 GPIO1（ADC1_CH0），用于实现火灾报警
和雨天自动收衣等安全联动功能。

第四部分 总结
4.1 可扩展之处
(1) 云端 MCP 扩展：在现有家居设备控制基础上，进一步接入 PC 桌面操作、
知识搜索、日程管理、邮件收发等 MCP 工具，拓展系统从“智能家居”
到“家庭智能助理”的应用边界。
(2) 多模态视觉能力扩展：在现有人脸识别基础上，进一步融合门口视频流、
异常人员检测、跌倒检测、手势识别等视觉能力，增强系统的安防感知和
无接触交互能力。
(3) 边缘 AI 推理优化：继续基于 ESP32-P4 的算力与 ESP-DL 等轻量化模型，
优化端侧视觉识别、环境判断和场景推理能力，减少对云端的依赖，提高
响应速度与隐私安全性。
(4) 多协议设备组网：在现有 WiFi/MQTT 通信架构基础上，扩展 Zigbee、蓝
牙 Mesh、Matter 等低功耗组网协议，提升系统对更多智能家居设备的兼
容性和扩展规模。
(5) 家庭能源管理扩展：结合用电监测、光伏发电、储能设备和分时电价策略，
实现家居设备能耗分析、智能调度和用电优化。
4.2 心得体会
本项目是一次从“AI 语音交互”到“多楼层 IoT 协同控制”的系统级工
程实践，涵盖了嵌入式开发中的硬件驱动、通信协议、RTOS 多任务调度、LVGL 图
形界面、AI 大模型接入与设备联动等多个核心方向。
在架构设计上，系统采用“P4 中控决策 + S3 从机执行”的分布式模式，
使我更加深刻地理解了模块解耦的重要性。P4 端负责任务调度、AI 交互、界面
显示和场景管理，从机端负责本层设备控制与传感器采集，各模块职责清晰，降
低了系统耦合度，也提升了后期调试和扩展的效率。
在从机设计上，项目采用标志位驱动的控制方式，将 MQTT 指令接收、设备
状态更新和 GPIO/舵机执行逻辑分离，使通信层与执行层互不干扰。这样的设计
让每个模块都可以独立开发和验证，也增强了系统在多设备联动场景下的稳定性。
在协议设计上，自定义 MQTT 设备控制协议的实践让我理解了“紧凑编码”
和“可扩展性”之间的平衡。通过统一命令字、设备编号、楼层编号和状态字段，
系统能够在较低通信开销下完成多设备控制与状态回传，也为后续新增设备类型
和场景模式预留了扩展空间。
在可靠性设计上，系统加入了传感器多次确认、启动预热忽略、手动覆盖保
护等机制，避免由于传感器抖动或误触发导致错误联动。这些细节让我认识到，
嵌入式系统不仅要“能运行”，还要在真实环境中具备稳定性和鲁棒性。
通过本项目，我最大的收获是学会了从需求倒推架构：先明确系统要解决的
问题，再设计数据流和控制链路，最后拆分模块接口与职责。这种自顶向下的工
程思维，使系统开发不再只是功能堆叠，而是围绕场景、稳定性和可扩展性进行
整体设计。
